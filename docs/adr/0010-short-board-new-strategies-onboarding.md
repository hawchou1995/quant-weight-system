# ADR-0010: 短线板块新策略接入口径（四字名 / 物理隔离 / 浏览器端竞价判定 / 复测门）

日期：2026-09-24 ｜ 状态：已接受 ｜ 来源：R-six-tasks-0924（用户批准「grill 全部按你推荐」）

## 背景

用户提出 6 项任务：① 恢复 gushi 登录并补采；② 打板族增加竞价/开盘期买入条件判定，满足者置顶（与超跌低开低吸同形态）；③ 把 bt520「双簿」框架里的纯左侧簿策略在复测可信后部署到短线板块并取四字名；④ 把 top1 个人口径 / jiandi 家族策略同样部署并取四字名；⑤ 所有策略所在子页面的四类内容（选股池/跟踪池/模拟盘/回测）**严禁共用**；⑥ 推送 GitHub + GitHub Pages，云端自动更新代码同步，新策略执行当日收盘数据更新。

三个前置事实冲突需要在决策层解决：

- **命名冲突**：本仓已有「A5 打板」（`backtest/a5_experiment/paper_daban_a5.py`，生产扫描器），而 bt520 框架内部也把「纯左侧簿」编号为 A5。二者是完全不同的策略。
- **口径冲突**：打板族 gap 区间在生产侧是**闭区间** `GAP_LO <= gap <= GAP_HI`（`paper_daban_a5.py:55`），在影子账本侧是**开区间** `GAP[0] < gap < GAP[1]`（`backtest/a5_paper_0914.py:56`）——边界票（正好 −5% / −2%）两边判定相反。
- **复用现状**：短线板块存在跨子标签共用（`#bt-short` 位于所有 `.subview` 之外，被 5 个子标签共用），与任务 ⑤ 直接冲突。

## 决定

**D1 · gushi 登录恢复顺序（诊断先行，零成本优先）**
先用 bsk 借用户真实浏览器**只读探活** i.gushi.in 的会话角色；探活不成再请用户在自动化 profile（`D:/Tools/chrome-auto-profile`）手动登录一次。**在任何情况下不提取/不打印 cookie、token、密码或身份字段。**

**D2 · 续费时机**
不在登录未恢复前续费。VIP 有效期至 2026-09-25 14:37:47、论坛积分 124，续费**不是**当前故障的瓶颈（真因是量化站 `role=guest`）；等到「登录恢复 + 当日采集成功」之后再续。既有护栏（每天 1 次、`_renewed_today()`）不变。

**D3 · 打板族竞价/开盘判定（沿用 ADR-0009 范式，判定放浏览器端）**
- 09:25 集合竞价结果出来后，用**真实今开**判定 `gap = 今开/昨收−1 ∈ [−5%,−2%]`，达标者**置顶**。
- 09:15–09:25 竞价期只显示「**竞价预判**」灰标（用集合竞价参考价），**不置顶、不计入命中**——竞价期拿不到权威「今开」。
- 置顶是**视图态**（只改 DOM 顺序），拒绝服务端常驻评估。

**D4 · 「复测数据可信」的门（部署前置）**
bt520 的**留出测试**（2016-01-04 → 2017-12-29，`PRE-REGISTRATION_20260924_final_candidate.md:149` 仍标「待授权」）+ **过拟合审计**双绿，才允许部署到短线板块并开**模拟盘**；未过门则**只上回测数据**，不开模拟盘。

**D5 · 命名（看板与 CONTEXT.md 一律用四字名）**
- bt520「纯左侧簿（主簿关闭）· 槽位5」→ **左侧捡漏**
- top1 个人口径 / jiandi 家族 → **热榜哨兵**
- `A1~A7` 仅作 bt520 内部代号，**不得**出现在看板与词表；「双簿 / 主簿 / 左侧簿」保留为 bt520 框架层术语。

**D6 · 隔离（任务 ⑤）**
新接入策略**严格物理隔离**：独立数据文件、独立卡片 id、独立回测产物、独立跟踪源登记。**现存共用点本轮只出报告、不动代码**（避免破坏在跑的盘中链路）。

## 追加决定（Round 2，2026-09-24 用户批准）

**D7 · gap 区间口径统一为闭区间**
以生产能力为准：`GAP_LO <= gap <= GAP_HI`（`backtest/a5_experiment/paper_daban_a5.py:55`）。影子账本 `backtest/a5_paper_0914.py:56` 由开区间改为闭区间，使边界票（正好 −5% / −2%）两边判定一致。理由：生产是账本真值源，影子是历史实验件。

**D8 · `#bt-short` 改为按子标签分区渲染**
不复制、不移动 DOM：参数化同一个 `bt_short_html()`（`build_dual_system.py:1006`），每张回测卡加 `data-sub` 标记对应子标签，由 `SUBNAV_JS` 控制显隐。使「回测数据」不再被 5 个子标签共用（响应任务 ⑤）。

**D9 · 两条新策略的模拟盘起点不同**
- **热榜哨兵**：沿用已写预注册的 `shadow_start = 2026-09-24` 开影子账本（`PRE-REGISTRATION_20260924_jiandi_top30_sentinel.md`）——预注册的意义就是先定日期不许改。
- **左侧捡漏**：先**只上回测数据**，不开模拟盘，直到 D4 复测门（bt520 留出测试 + 过拟合审计）双绿。

**D10 · bt520 信号逻辑移植进本仓**
若 bt520 无单日信号入口，将 Book B（左侧簿）信号逻辑移植进本仓（与既有 `a5_experiment` 搬入仓库同法），使云端链路不依赖本机 E 盘。最终可行性以「bt520 日更能力补勘」结论为准（该结论未回前不动手）。

**执行顺序约束**：D8 与任务 ②（打板族竞价判定 + 置顶）都会改动 `intraday_live.py` / `build_dual_system.py` 同一区域，必须**串行**施工、各自独立验收，不得并发改同一文件。
