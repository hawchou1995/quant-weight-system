# ADR-0009: 超跌低开低吸盘中买点判定放浏览器端（拒绝服务端常驻评估）

日期：2026-09-22 ｜ 状态：已接受 ｜ 来源：R-qlch-live-0923（用户批准的「盘中实时买点判定 + 达标置顶 + 盘中净值」）

## 背景

超跌低开低吸的买点是**盘中瞬时条件**：开盘跳空 `gap = 今开/昨收−1`（当日恒定）、盘中回落 `现价/昨收−1`（逐笔变）。
看板此前只有「今收 × [0.95, 0.98]」的静态价格带与收盘后的六臂模拟盘/跟踪池——用户要的是盘中就能看到「今天哪些候选真的低开达标」，以及「影子盘此刻大约值多少」（净值估算）。

两条实现路线：① 服务端常驻评估（定时拉行情 → 判定 → 写 json / 动账本 / 重新部署页面）；② 浏览器端评估（打开页面时直连行情源，就地判定）。

## 决定

1. 实时买点判定与盘中净值估算**全部放浏览器端**：`intraday_live.py:QLCH_JS`（注入产物 `<script>`）+ 构建期内嵌的 `window.QLCH` 快照（候选 / 参数 / 六臂账本净值）。
2. **拒绝服务端常驻评估**：不新增进程、定时任务、线上产物，不改收盘链的记账口径。
3. 「置顶」明确为**视图态**：只改 DOM 顺序与样式，不写回任何 json/账本，不改变 depth rank、候选取样与 K=3 名额。
4. 首次触发时间戳只落 **localStorage**（`quant_qlch_trig_v1`），跨日按 `window.QLCH.as_of` 作废；不落任何服务端状态。

## 理由

- **零落盘**：判定结果不进入任何数据文件；收盘链（候选生成、账本记账、部署）完全不受影响，出事只需摘掉一个 `<script>` 块。
- **复用已验证的盘中层（#4b）**：行情通道（东财 `ulist` 主源 / 腾讯 `q=` 兜底）、防串码名称校验、开市判定、收盘链静默窗都不重写。
- **服务端方案代价明显更大**：要一台常开机器（或定时任务）在 09:15–15:05 轮询、要落盘中间态、要每日部署；而收益与浏览器端相同 —— 买点判定的全部输入（今开、昨收、现价 + 候选今收）在行情接口里都拿得到。

## 代价

- **页面没开就不算**：页面未打开或收盘后才打开时，盘中达标情况不回溯、不落盘（历史可回放：候选与账本本来就在收盘链里）。后续若确实需要「页面没开也算」，须另立预注册加服务端评估（本 ADR 不授权）。
- 需要向产物内嵌一份数据快照（`window.QLCH`，约 +26 KB）。
- 判定口径依赖行情接口的今开/昨收字段（东财 `f17/f18`、腾讯 `[4]/[5]`）；字段缺失时只能降级（回退算法或标「无法判定」，不计入置顶）。
- **盘中净值的口径与生产记账对齐，但只算「持仓腿」**：`nav_now = nav_prev × (1 + Σ w_i×(现价_i/基准_i − 1))`，基准 = **上一交易日收盘**（行情昨收；仅当 `entry_date == 行情日` 这一档新开仓用入场价，同 `qlch_paper_20260921.py:379-384`），**开仓腿不扣成本**（`COST_RT` 在生产里只作用于出场腿 `:391`）。**未计入**闲置资金的国债ETF 收益腿（生产 `:394-413` 的 `cash_w × cashret`）—— 盘中要拿到该腿当日收益需额外取 CASH_CODE 行情，当前按「持仓腿」估算并在卡片注明「估算，非记账值」。
- **当日已记账的不再叠加**（修正 2）：账本 `equity[-1].date == 行情日` 时直接显示账本净值 + 「已收盘记账」；行情时间戳缺失时同样不叠加（宁可少算，绝不把已记账的收益算两遍）。
- **开盘前不再显示上一交易日 gap 视图**（修正 3，已修复）：买点判定只在「行情日 > 候选 `as_of`」时生效，否则整卡进入「待开盘判定」态（不置顶、不贴标、计数 0，徽标显示 `待开盘判定（as_of …）`）。判定用的「今天」取自**行情时间戳**（腾讯 `[30]`，来源交易所），不用本地日期 —— 节假日/补班/跨零点都不会误判。

## 替代方案（被否）

- **服务端定时评估 + 写 json（被否）**：需常驻 + 落盘 + 每日部署；且把「盘中瞬时值」固化成数据文件，与「账本记账以收盘链为准」的口径冲突。
- **服务端只算不落盘（被否）**：仍需常驻进程与新的线上产物；浏览器端已能直连行情源，属重复建设。
- **收盘后回溯计算当日达标（被否）**：拿到的是历史结论，不是用户要的「盘中看得见」。

- 验收口径随本 ADR 归档：`_verify_qlch_live.py`（合成行情注入 + 行情时间戳注入，45 条断言：判定/置顶/幂等/跨日/净值口径/未叠加/待开盘判定/基准规则）+ `_verify_treelive_0922.py`（树图层回归，未改）。

## 修订（2026-09-22 晚，口径修正）

初版实现与生产记账有三处不一致，已按 `qlch_paper_20260921.py:371-418` 修正（细节见上「代价」段）：
① 盘中净值基准改为**昨收**、开仓腿**不扣成本**（初版用入场价且扣了成本）；② 当日已记账则**不再叠加**；
③ 盘前/信号日当日改为「**待开盘判定**」（初版会把上一交易日的 gap 当今天显示）。

- 盘中买点/置顶/盘中净值的唯一真源是 `intraday_live.py:QLCH_JS`；看板只负责内嵌快照（`build_dual_system.py:qlch_live_payload()`）。

## 修订（2026-09-22 更晚，第 3 轮：线上验收发现）
- ④ **闸门不得依赖 `live`**：收盘后 `S.live=false`，旧实现会让闸门失效 → 拿「当日已发生的开盘」比对「次日买入带」。改为只由「行情日 vs `as_of`」决定。
- ⑤ **徽标分离**：qlch 徽标改 `badge qlch-badge`（不带 `badge-live`），与盘中层 `markCard` 的「实时 HH:MM:SS」并存互不覆盖。
- ⑥ **真实刷新路径接入**：盘中层 `refresh()` 内部调的是 IIFE 局部 `applyQuotes`，外部包装拦不到 → 新增可选钩子 `window.QLCH_ON_QUOTES`（无钩子零开销，树图腿未动）。**此缺陷若不修，本功能在真实页面加载路径上不会生效。**
