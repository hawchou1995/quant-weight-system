# 跌停封死出场修复与复验（2026-10-13）

## 1. 缺陷（由 G5 发现，来源 gushi topic/1010 第②条）

`backtest/hengpan_fangliang_dikai_0925/oos_run_v16_executable.py` 的 `exit_of()` **完全不查卖出可行性**：它只处理「收盘缺失顺延」，却没处理「当日跌停封死卖不掉」。于是：

```
sym=sz000042  2020-01-23 买入 9.84  →  原出场 2020-02-03 @ 8.73（−11.34%）
```

本机日线真值：2020-02-03 该股 **o=h=l=c=8.73，前收 9.70 → −10.00% 一字跌停**，全天只有跌停价一个价，**没有任何高于跌停价的成交** → 按 1010 口径必须顺延到下一可卖日。策略却把出场记在 8.73，属**乐观出场**。

## 2. 修复（只动 v1.6，v1.5 冻结脚本一个字节没碰）

`exit_of()` 改为按候选日循环，每天先过一道**卖出可行性**判定：

```python
def sell_blocked(i, j, C, H, sym):
    """当日跌停封死（全天内最高价已触及跌停价）→ 卖不出。
    真值源：engine.session.limit_prices（前收×板块档位）+ reaches_limit_down（含 tick 容差带）"""
```

- 封死日 → 跳过、顺延到下一可卖日（与既有「收盘缺失顺延」共用 **≤6 日**上限）；
- 6 日内无可卖日 → 仍是末段最坏全损（`exit_flag=2`，语义不变）；
- 顺延发生 → `exit_flag=1`（沿用既有"顺延"标记，不新增枚举）；
- 调用点补传 `sym=syms[j]`（板块档位需要代码）。
