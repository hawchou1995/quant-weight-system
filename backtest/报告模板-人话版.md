## 一、词汇表（唯一口径，禁止同义混用）

### 1.1 核心八词（看板已有，直接沿用）

| 中文名 | 一句话说人话 | 怎么看（判据） |
|---|---|---|
| **回测收益** | 从开始到现在一共赚了百分之多少 | 正数才是赚 |
| **年化** | 折成年化，每年平均赚百分之多少 | 要和沪深300 比，不等于跑赢 |
| **最大回撤** | 从最高点跌下来最惨的一次，跌了多少 | 越小越好；超过 −30% 大多数人扛不住 |
| **夏普** | 每承担一份波动，换来多少超额回报 | >1 尚可，>2 优秀，<0 是负回报 |
| **胜率** | 十笔里赢几笔 | 单独看没用，要配盈亏比 |
| **累计收益** | 累计赚的总额（含未平仓） | 与"回测收益"同义，避免两词混用 |
| **净值** | 一元本金现在值多少钱 | 起点归一为 1 或 100 |
| **持仓 / 仓位** | 现在买了什么、占多少钱 | — |

### 1.2 补充词（tearsheet 技能有、项目报告从未用过）

| 中文名 | 一句话说人话 | 怎么看 |
|---|---|---|
| **盈亏比** | 平均每笔赚的 ÷ 平均每笔亏的 | >1.5 配合胜率 40% 就能赚 |
| **卡玛** | 年化 ÷ 最大回撤 | 衡量"赚钱效率"，>0.5 尚可 |
| **索提诺** | 像夏普，但只罚下跌不罚上涨 | 比夏普公道，>1.5 好 |
| **超额收益** | 比同期大盘多赚了多少 | 这才是策略的本事 |
| **信息比率** | 每单位超额波动换来多少超额收益 | 像"超额收益版夏普" |
| **回撤持续期** | 最惨那次跌了多久才见底 | 天数越短越好 |
| **恢复时间** | 从那之后多久才回到前高 | 越长越难熬 |
| **月度收益热力图** | 每个月赚亏的色块图 | 一眼看出哪几个月最难 |

### 1.3 内部术语 → 人话对照（研究报告里术语必须并存，但要括注）

| 术语 | 人话说法 | 为什么要保留 |
|---|---|---|
| `bp` | **基点**（100 bp = 1%） | 成本/费率精度需要 |
| `phmed` | **20 种起始日分别回测后取中位数的夏普** | 防"起点挑得好" |
| `IC` | **因子预测力**（因子与未来涨跌的相关性） | 因子研究标准量 |
| `uniq` | **涉及的股票只数** | 与"交易笔数"区分（同一只票会重复出现） |
| `exc_mean` | **平均超额收益** | 即上面「超额收益」的均值 |
| `t 值` | **这个结果有多不可能是巧合**（越大越不可能是运气） | 统计必需 |
| `DSR` | **扣掉试错次数之后的夏普** | 试了 359 种方案后，第一名的成绩要打折看 |
| `PBO` | **过拟合概率** | 换个时间段就失效的可能性 |
| `MDD` / `CAGR` | **最大回撤 / 年化**（看板早就中文化了，报告里不该再写英文） | — |

## 五、补充（0928 代理实测后加入）

### 5.1 中文指标名**有官方出处**——用标准的，不用我编的

代理从**掘金量化官方文档**与**聚宽 API 文档**取到逐字字段名。标准排布（聚宽回测结果表原文顺序）：

```
策略收益 | 策略年化收益 | 超额收益 | 基准收益 | 阿尔法 | 贝塔 | 夏普比率 | 胜率 | 盈亏比 |
最大回撤 | 索提诺比率 | 日胜率 | 盈利次数 | 亏损次数 | 信息比率 | 策略波动率 | 基准波动率 | 最大回撤区间
```

**官方公式（掘金，逐字）**：
- 年化收益率 = `(期末净值/期初净值)^(250/交易日数量) − 1`（**用 250，不是 252**）
- **胜率 = 平仓盈利次数 ÷（盈利次数+亏损次数）**，**含费用、不含未平仓浮盈**
- 卡玛比率 = `年化收益率 / |最大回撤|`
- 夏普比率 = `(年化收益率 − 无风险利率) / 年化波动率`

⇒ **本模板 §一 的词汇表按此对齐；不再自创叫法。**

### 5.2 「胜率」是最大的坑：三个口径同名不同义

| 口径 | 定义 | 谁在用 |
|---|---|---|
| **按期数** | 盈利的**天数/月数**占比 | `quantstats`（其 `win_rate()` 源码 docstring 原文："percentage of profitable **periods**"） |
| **按笔数** | 平仓盈利次数 ÷ 总平仓次数 | 掘金 / 聚宽 / backtrader（**这才是用户认的**） |
| **相对基准** | 跑赢基准的天数占比 | 聚宽的「日胜率」 |

⇒ **凡报"胜率"，必须标注是"按笔"还是"按天"**。
**西方主流 tearsheet 库（quantstats/pyfolio/empyrical）都没有"按笔胜率"**——pyfolio 全库 `win_rate` 命中 **0 次**。
本项目要的「胜率」是**按笔**，必须从**成交记录**自己算，不能直接取库的 `win_rate()`。

### 5.3 其余口径分歧（报数必须声明，否则跨表不可比）

| 分歧点 | 各家做法 | 本模板规定 |
|---|---|---|
| 夏普年化因子 | empyrical/quantstats=**252**；掘金=**250**；有文用 365 | **声明用哪个**；项目统一**252**（与既有脚本一致） |
| 无风险利率 | quantstats 默认 **0**；国内平台可配置 | 报告里**写明取值** |
| **最大回撤符号** | 西方库输出**负数**（−38.28%）；聚宽/掘金报表是**正数** | **统一写成负号**（口语上更自然："跌了 38%"） |
| 卡玛窗口 | 原始定义=**36 个月滚动**；库实现=**全样本** | 注明"本表为全样本口径" |
| 索提诺分母 | 一种数据可出 4 个数（普通/Smart/÷√2 组合） | 只在必要时报，且**声明分母** |
| 年化收益算法 | 复利（标准）vs **qlib 明写用累加**（其官方 docstring 承认"different from the definition"） | **只用复利**；跨工具比数前先确认对方算法 |

### 5.5 「t 值 / 试错次数」的人话替代

用 `ffn` 的 `calc_deflated_sharpe_ratio` 与 `calc_prob_backtest_overfitting`（PBO）
→ 输出「**回测过拟合概率 XX%**」，比 t 值直观得多，且已是本项目 ★175/★177 想表达的意思。
