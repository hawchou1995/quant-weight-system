## 九、① 内存保护修复（2026-09-16，R-memfix-0916）

**触发**：09-15 每日链在 `fund_nav_update`（3042 只基金净值刷新）之后跑 `build_short_pool` 时，
出现**间歇性原生崩溃 exit 0xC0000005（访问违规）**；根因排查：该脚本与后续步骤**均不引用任何本轮改动文件**（grep 空），
单独重跑 302s **exit 0 成功** → 判定为**内存压力下的原生分配失败**（实测当时内存占用 84%+、可用 <1GB）。

**根因定位（全量用法审计）**：`short_engine.load_stock_pool()` 把**全市场 5080 只**的因子 DataFrame
（每只约 2600 行 × 20+ 列 float64）**全部常驻内存**；而下游全部用法的最长回看仅 **60 行**：

| 下游用法 | 实际回看需求 |
|---|---|
| `short_factors` | `c.shift(60)` / 各 `rolling(20)` |
| `_hit_count` | `rolling(60)` / `rolling(10)` |
| 主打分循环 | `ddf.loc[as_of]` / `ddf.iloc[-1]` |
| `_ref_snap` | `_cls.iloc[-1] / _cls.iloc[-2]` |
| 新鲜度/停牌判定 | `df.index[-1]` |

**处置（三处最小改动，零行为改变）**

| # | 文件 | 改动 |
|---|---|---|
| 1 | `short_engine.py` | `load_stock_pool(tail_n=None)` 新增可选参数（默认 None = 全历史，**研究/回测路径行为不变**）；截尾模式启用 `gc.collect()` + RSS 日志；新增 `_rss_mb()` |
| 2 | `build_short_pool.py:565` | 生产路径改为 `load_stock_pool(tail_n=300)`（= 最长回看 60 行的 **5× 余量**） |
| 3 | `daily_refresh.py` | 步骤失败时若 returncode ∈ {3221225477, -1073741819}（0xC0000005 两种有符号表示）→ `gc.collect()` + 等 5s + **原样重试一次**，仍失败才走原失败路径 |

1. **受控 A/B 内存测量**（同批 400 只，两种模式各加载一次）：

   真实运行实测：`load_stock_pool 完成 5080 只 RSS 664MB (138s) tail_n=300`。
2. **零行为改变（指纹逐位对拍）**：改动前后 `short_pool.json` 的 `{asof, market_gate, tiers}` 指纹
