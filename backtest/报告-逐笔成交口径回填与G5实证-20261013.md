# 逐笔成交口径回填与 G5 实证（2026-10-13）

## 1. 为什么做这件事

`tools/gate_trading_clock.py` 的 **G5 成交口径三查**（来源 gushi topic/1010，见 `报告-gushi社区回测内容与Agent加固-20261013.md`）需要成交日的 open/high/low 与前收；但本仓历史 `*trades*.jsonl`（76,588 条）**只记 `entry_open`/`exit_px`，不带 bar 快照**，于是 G5 只能报「不可判 103,464 腿」，等于装了却没咬到东西。

本轮补齐取证链：写了一个**只读回填工具**，把当日 bar 按 `(sym, date)` 从本机只读日线并入逐笔记录（原文件不动），然后让 G5 在真实记录上实跑。

## 2. 做了什么（可复现）

```powershell
# 1) 回填当日 bar（entry bar + exit bar + 各自前收），不改任何收益字段
python tools/backfill_trade_bars.py backtest/hengpan_fangliang_dikai_0925/oos_v16_trades.jsonl <scratch>/oos_v16_trades_bar.jsonl --json <scratch>/backfill_v16.json
# 2) 让门禁在回填件上实跑
python tools/gate_trading_clock.py --root <含回填件的目录> --json <scratch>/g5_real.json
python tools/gate_trading_clock.py --root <含回填件的目录> --strict-fill
```

| **违规** | **1** | 见 §3 |

## 3. 唯一一条真违规：`sz000042` 2020-02-03 按跌停价卖出

```
✗ G5c 跌停封死却记成交  sym=sz000042 date=2020-02-03 side=sell px=8.73
   —— 当日 high 8.73 已触及跌停 8.73（全天封死、卖不掉），须顺延到下一可卖日再计价
```

本机日线真值：

| 日期 | open | high | low | close | 前收 | 跌停价 | 说明 |
|---|---|---|---|---|---|---|---|
| 2020-01-23 | 9.84 | 9.99 | 9.66 | 9.70 | — | — | 节前最后交易日 |
| **2020-02-03** | **8.73** | **8.73** | **8.73** | **8.73** | 9.70 | 8.73 | **一字跌停（−10.00%），全天只有跌停价一个价** |
| 2020-02-04 | 8.48 | 8.82 | 8.09 | 8.70 | 8.73 | 7.86 | 次日可卖，收盘 8.70 |

即：节后首个交易日全市场一字跌停，该股 `o=h=l=c=8.73`，**没有任何高于跌停价的成交**；策略却把出场记在 8.73。按 topic/1010 第②条，这笔必须顺延到 T+2（2020-02-04 收盘 **8.70**，比 8.73 更差）。

- 这是**历史回测的一次乐观出场**，不是本轮改动引入的：记录本身就是 8.73。
- 影响面：该文件 1,182 笔成交里 1 笔命中；量级小，但**类**是真的（全市场跌停日）——若策略在别的市场级跌停日也有出场，G5 会逐条报出来。
- 本轮**没有**改这些历史结果，也没有重跑回测；只把判据装上并给出证据。

## 4. 过程中修掉的两类假阳性（都记在门禁代码注释里）

装上 G5/G4b 后先出了一批假阳性，逐条取证后确认是**门禁的锅**，已修：

1. **尺度混算（5 条）**：`probe_fill_tradability` 拿**记录里的原始前收**（如 sz000418 2016-01-12 的 17.30）去比**回填的本机前复权 bar**（今开 20.53）→ 算出「涨停 19.03」→ 误判「涨停开盘买不进」。本机真值：前收 21.04、今开 20.53 = **−2.42%**，根本没触涨停。
   修法：G4b 一律优先用**本条 bar 自带的 `prev_close`**，只有 bar 没有时才退回记录字段；G5 早就这么做，且 G5 的三条判据本身**与价格尺度无关**（只看 open/high/low 与前收的相对关系）。
2. **审了没成交的记录（5 条）**：`filled=0` / `entry_px` 为空或 0 的记录（如 sh601028 2016-07-21 一字涨停、sz002499 2016-04-15 停牌）被拿去判「能不能成交」——空审必然报错。
   修法：G4b 与 G5 都只审**声称成交**的腿；`entry_px=0`（未成交哨兵）不再当作成交价。

修完后：G4b 违规 0，G5 违规 1（即 §3 那条真违规）。

### 复权口径（为什么 1,803 条入场价对不上）

本机日线 `D:/Documents/Quant data/data_full` 是**前复权**（部分标的价格未取整，如 5.685599…），而历史记录里的 `entry_open`/`prev_close` 是**原始成交价**。两者比值在同一只票上是**恒定的复权因子**（跨除权事件会变）。因此：

- 门禁**不做**「记录价 vs bar 价」的跨口径比较；判定只用 bar 自身或记录自身的**同尺度**字段。
- 1,803 条「差 >1 分」正是复权差，不是数据错误（与 gushi 那次核对的结论一致）。

| 范围 | 逐笔记录 | G5 可判 | G5 不可判 |
|---|---:|---:|---:|

也就是说：**门禁本身已验证有效（注入式自检 3/4、正例 0/0、盲挂放行 ≥1），并且在真实记录上报出了 1 条真违规**；但要让它在全仓生效，需要对各条回测链的逐笔产物跑一遍 `backfill_trade_bars.py`（或让产出端直接写 bar 快照）。这一步还没做全。
