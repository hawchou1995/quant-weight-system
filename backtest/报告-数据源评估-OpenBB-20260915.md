# 报告 · 数据源评估：OpenBB —— **不吸收**（2026-09-15）

> 素材：微信公众号文章《OpenBB 开源金融数据平台》（https://mp.weixin.qq.com/s/0XFykPMGRtqWnaQHycHpcQ）
> 用户指令：「此数据源评估是否吸收」。评估方式：官方文档取证 + **本机实测裁决**（安装→查数→对拍→清理）。

## 一、结论

**不吸收为数据源**（对现有 A 股研究体系零增量，且多处更差）；**平台层（provider 抽象 / openbb-mcp-server）列为观察项**，当前无落地需求。测试环境已清理（`D:/Tools/venvs/openbb_test` 389MB 已删，重建命令见 §五）。

## 二、它是什么（fact check）

OpenBB = **provider 聚合平台**，官方自述「**does not host or serve any data**，只提供连接器」——价值在"一次对接、处处可用"的抽象层（Python / CLI / REST API / Workspace UI / MCP），不在数据本身。核心 ODP 为 AGPLv3；**公司已放弃商业化：2026-08-25 官方公告全产品套件转 permissive 开源**（生态维护存在不确定性，列观察项）。

## 三、实测结果（本机，openbb 4.7.2）

官方 provider 全表（docs.openbb.co）亦确认：全是美/全球源（FRED/IMF/OECD/SEC/FMP/Polygon/Yahoo…），**A 股需社区扩展**。

## 四、保留的观察项（不吸收，但记录）

1. **openbb-mcp-server**（把 FastAPI 服务一键转 MCP）——若未来有"自建数据服务 → Agent 调用"需求可参考其形态；
2. **宏观数据源**（FRED/IMF/OECD/BLS/EIA，免费公开）——当前体系纯 A 股不用；若未来做宏观 regime / 择时因子，可直接走这些官方 API（无需经 OpenBB）；
3. **provider 抽象层设计**——其"每个数据源一个可插拔扩展"的架构，对我们 pipeline 分层有参考价值。
