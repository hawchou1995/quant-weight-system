## 三、重点回答：这 33 个工具能不能增强复盘与选题？

**结论：能，且价值集中在"复盘归因 + 选题"这条线上，不在因子线上。**

### 用法 1（最推荐）★ 异动/涨停个股的"消息面归因"自动化

**解决什么**：现在复盘涨停池/龙虎榜只能看价格与资金流，**"为什么涨"要靠人肉翻公告和新闻**。
本轴可在一次调用链里把 T-1~T 的公告+新闻+事件时间线拼出来。

```bash
# ① 事件时间线（最近 30 天，标的首选）
python connector_tongzhou.py call doc_search__get_entity_event_timeline \
  '{"ticker":"600519.SH","days":30,"limit":20}'

# ② 当期货公告（类型枚举，最多 50 条）
python connector_tongzhou.py call doc_search__search_announcements \
  '{"ticker":"600519.SH","content_type":"股权激励","days":90,"limit":50}'

# ③ 公司新闻（含 event_type / related_industry）
python connector_tongzhou.py call doc_search__search_company_news \
  '{"ticker":"600519.SH","days":7,"limit":20}'

# ④ 原文取证（doc_id 从上面返回里取，禁止持久化）
python connector_tongzhou.py call doc_search__get_document \
  '{"doc_id":"ev1_xxxxxxxx","doc_type":"announcement","max_length":2000}'
```

**落在我们哪条线**：涨停池/`short_pool` 盘后复盘、`detect_stock_patterns` 出来后的归因环节。
**替代/补充什么**：替代手工翻巨潮/东财；补充本地只有价格与资金流的空白。
**验收方式**：取本地涨停池某日 N=20 只，逐只跑链路，人工核对"是否有对应公告/新闻支撑"，
记录 覆盖率 与 人工耗时（对照现有复盘流程）。

**已知边界（必须写进使用规范）**：
- `limit` 硬上限 50 且**无翻页** → 只做"归因取样"，**绝不能当计数用**；
- `content_type` 只能用实测闭集（§1.1 第 1 行）；
- 公告检索历史实际只有约 1 年余；
- `doc_id`/`evidence_ref` 是短期 opaque 引用，**当次会话用完即弃**，不准落库。

### 用法 2 ★ 行业观点拥挤度 / 情绪（选题用）

**解决什么**：选题时要判断"哪个行业已经被讲烂了 / 哪些行业观点正在转向"。

```bash
# 目录 → sector_id（100 个行业，一次拿全）
python connector_tongzhou.py call same_boat__list_research_sectors '{"type":"行业研究","limit":100}'

# 单行业近 1 月观点：sentiment_score / analyst_count / 条数
python connector_tongzhou.py call same_boat__list_sector_viewpoints \
  '{"sector_id":"1001001","time_range":"1m","limit":50}'

# 当日报表全量快照（无日期参数，只能取当日）
python connector_tongzhou.py call same_boat__list_market_viewpoints '{"limit":200}'

# 观点全文 + 图表证据
python connector_tongzhou.py call same_boat__get_market_viewpoint_detail \
  '{"viewpoint_id":"7505768184402677761"}'

# 回链交付到微信小程序
python connector_tongzhou.py call same_boat__generate_content_url_link \
  '{"content_type":"market_viewpoint","id":"7505768184402677761"}'
```

**可提取字段**：`sentiment_score`（实测 55~82）、`analyst_count`（实测 80~163）、`sentiment`（positive/neutral）、条数。
**落在我们哪条线**：行业轮动选题、`v9_tiers` 行业超配讨论。
**验收方式**：对 100 个行业取 `time_range=1m` 的 `sentiment_score` 均值/条数，
与本地行业动量、上一轮已转的**行业资金流**做 Spearman 对拍；**只作为描述性拥挤度指标**，不得直接当信号。

**硬边界**：**历史只有 1 年**（2025-09-17 起，氯碱翻到底 648 条）；`list_market_viewpoints` 只是当日快照。


**可提取**：`sample_count` + `yearly_counts`（茅台 5y：391 条 / 2021~2026 逐年 2/81/55/60/92/101）。
**落在我们哪条线**：`a5_pool` 价值池的"卖方关注度"维度、个股深度研究选题。
**验收方式**：抽 10 只票对拍"研报条数排序"是否与常识一致（大盘白马 > 小票）；
**注意 `mapped_count=0`** —— 只信 `sample_count`，不要用映射结果。

## 四、PIT 申报（凡从新闻/研报取的字段）

| 字段/来源 | 发布时点 | 我们何时能拿到 | 判定 |
|---|---|---|---|
| `publish_date`（doc_search 全家族，公告到秒 `2026-06-10T19:10:08`） | 媒体/巨潮披露时点 | 披露后即可（同源官方披露） | ✅ **可用作 PIT 锚点**，决策用 T 日盘后已披露者 |
| `event_date`（`search_normalized_events`/`get_entity_event_timeline`，带时区） | 事件发生/披露 | 同上 | ✅ 安全 |
| `publish_time`（`market_viewpoint` / `market_news`） | 实测观点集中在凌晨 00:05~07:22 发布，要闻 09:23~22:51 | 发布后 | ✅ 安全（但**必须确认是内容发布而非平台入库时间**——本轮无法从返回中区分，保守按"发布当日盘后不可用、次日可用"处理） |

| `search_backtested_events` / `get_event_backtest` 的 `returns/up_probability` | 事件已成熟后才生成 | 事后 | ❌ **前视，禁用于回测**（沿用上一轮判词） |

| `sentiment_score` / `analyst_count` / `popularity_score` / `importance_score` | 平台生成 | 生成时点未申报 | ⚠️ **算法生成时点未申报** → 用于复盘可以，**进因子需先确认生成时点**（本轮已因历史仅 1 年排除） |
