## 二、新冻结定义（逐字，取代原 §二.4）

1. `room := K − 买入动作前的未平仓笔数`（K=3；沿用原 §二.4 的槽位占用时点：当日到期出场者在买入时**仍占槽**）。
2. `free_slots := 当日买入动作前的空槽数 ≡ room`。
3. **`alloc := 当日可用现金 / len(free_slots)`**（逐字 = `cash_before_buy / room`）。
4. 由此推出的冻结推论（逐条，全部加运行期断言，见 §七）：
   - **单票名义额 ≤ 当日可用现金 / K**：`alloc = cash/room ≤ cash/K`（因 `room ≤ K`）⇒ **1/K 单票上限在「当日信号数 < 空槽数」的日子依然成立**（这是本修订的全部目的）；
   - **组合名义敞口 ≤ 当日可用现金**：当日最多买 `min(信号数, room)` 笔、每笔 `= cash/room` ⇒ `Σ(名义额) = n_buy × cash/room ≤ cash` ⇒ **无杠杆**，且 `cash_after_buy = cash − Σ(名义额) ≥ 0`；
   - 每笔 `alloc` 在入场时一次定死（**不补仓、不摊平**，与原文一致）；
   - **信号数 < 空槽数 ⇒ 留闲置现金**（`Σ(名义额) < cash`）。这是本修订与旧主口径的**唯一实质差别**，其规模在 §九 量化。
5. **修订理由（用户 2026-10-10 拍板原话意思，逐字转写）**：
   > K=3 槽位若允许「某天只有 1 个信号就把全部现金压进那一只」，等于当天变成 1 槽，**没有 1/K 上限**，那不叫 K=3。
   ⇒ 字面槽位语义守住 1/K 单票上限；旧定义在「当日信号数 < 空槽数」时会把全部现金压进少数标的（极端情形 = 当日 1 只信号 ⇒ `alloc = 全部现金`，单票集中度 100%）。
   **已知代价（登记，不构成回退理由）**：上一轮已公开的敏感性读数显示字面口径把累计从 +222.49% 打到 +87.29%，主因是「闲置现金长期偏高」——这正是 1/K 上限的代价。
