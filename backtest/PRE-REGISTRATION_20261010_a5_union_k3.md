6. 每日：入场 `cash -= alloc`；出场 `cash += alloc × (1 + net)`；`NAV[d] = cash + Σ alloc × close[d]/entry_px`。

### 3.2 冻结键（逐字）

> **排序键 := 事件表原始行序。在本事件表上，该行序在「按入场日 `e` 稳定排序（`kind="mergesort"`）」之后，逐日恒等于 `code` 字典序升序。**

逐字落地：
- 排序：**仅按 `e` 升序，稳定排序（mergesort）**；**同一 `e` 内不再做任何重排**，保持事件表原始相对行序；
- 该原始相对行序的实测内容 = **`code` 字符串字典序升序**（`sh600017 < sh600018 < sz000723 < …`）；
- 因此 `take = 当日信号.head(空槽数)` 中「当日信号」的次序 = `code` 升序；
- **运行期断言（强制）**：脚本对每个多信号日断言 `list(当日 code) == sorted(当日 code)`，**违例即 `raise` 退出**（不静默回退到别的键）。

### 3.3 为什么是这个键（理由，三条）

1. **它等于线上观察盘自身的到达序** —— 冻结它不是发明，而是照抄线上：
   - `backtest/a5_experiment/paper_daban_a5.py:461` `files = sorted(glob.glob(os.path.join(DATA_DIR, '*.csv')))`（文件名 = `code.csv` ⇒ **code 字典序**）；

   - `:636` `for code, feat in feats.items():` ⇒ 阶段1 生成的观察清单本身即 **code 升序**；
   - `:675` 追加进 `state['watchlist']`（保序）；`:527` 阶段2 `for w in state.get('watchlist', []):` ⇒ **同一天要入场的信号，处理次序 = code 升序**。
   - 由于阶段2 只处理 `w['sb_date'] == D1`（`:529`），**同一个入场日上的所有信号都来自同一个信号日**，其清单次序就是该信号日的 code 升序。⇒ 线上「谁先进」的确定序 = **code 升序**。
2. **它与事件表原始行序一致** —— 事件表按 `code` 升序、同 `code` 内按 `buy` 升序落盘（实测 1,059 行）；故「按 `e` 稳定排序」后在每个多信号日内保序 = code 升序。实测并集 396 中有 **62 个多信号日**（单日最多 14 只），**逐日核验违例数 = 0**。
3. **它 = 上一轮 S1 的隐式键** —— 上一轮 `port_full(A1, …, K=3)` 传入的 `A1` 已按 `e` 稳定排序（`a5_union_portfolio_1010.py:191`），`entr.head(room)`（`:81`）用的就是该行序。⇒ 冻结键与已公开的 K=3 读数（+222.49% / 12.945% / 0.6139 / −39.97% / 247 / 52.63%）**同口径**，**本轮不引入任何新自由度**；本轮做的事只是把这个隐式键**写成明文并加断言**。
